# Rule: server Nest conventions, buses, persistence & auth

**Scope:** `packages/server/` — read before writing handlers, wiring modules, publishing events, or touching SQL/auth.
**Backing ADRs:** 0004 (errors as tagged classes), 0006 (typed bus over `@nestjs/cqrs`), 0007 (unit of work + one event bus), 0012 (observability/spans), 0016–0017 (auth via Zitadel BFF), 0020 (per-module DB schemas), 0033 (the port).

- **Errors are tagged classes, returned not thrown** (ADR-0004). A domain error is `class TodoNotFound extends TaggedError("TodoNotFound")<{ readonly todoId: TodoId }> {}` (`platform/ddd/contracts/tagged-error.ts`; it does not extend `Error` and must be extended by a class — `TaggedError("X")` alone is not a type). Domain errors live in `domain/`, contract errors in `@org/contracts/HttpErrors` (`defineError(tag, status, shape, description)`), and the endpoint maps domain → contract with `unwrapOrThrow(result, { TodoNotFound: (e) => problem(HttpErrors.NotFound, { message: … }), PersistenceUnavailable: serviceUnavailable })` — exhaustive by tag, or it does not compile. A thrown error anywhere is a defect: `ProblemFilter` turns an `HttpProblem` into its status and body and everything else into a 500.
- **Typed bus** (ADR-0006). A message is `class CreateTodoCommand extends Command<CreateTodoResult>` (from `@nestjs/cqrs`) with `constructor(public readonly payload: CreateTodoPayload)`; `commandBus.execute(new CreateTodoCommand({...}))` returns `Promise<CreateTodoResult>` — the message is the single source of truth, no casts. Always declare the result as an explicit alias, `export type XResult = Result<A, E1 | E2>`: TypeScript does not infer a union of `Ok`/`Err` branches, so `run<XResult>` and `Command<XResult>` both name it. Inject **`AppCommandBus` / `AppQueryBus`** (`platform/cqrs/`), never Nest's `CommandBus`/`QueryBus` directly: the wrappers open `command.<Name>` / `query.<Name>` spans with the attributes from the module's `xCommandSpanAttributes` map, keyed by the message **class name** — so a message class is never renamed without its span key. Boot completeness is `assertHandlersCover` in `<feature>.handlers.test.ts`, not a runtime check.
- **Unit-of-work boundary + one event bus** (ADR-0007). The boundary is `@org/unit-of-work` and the bus is `@org/event-bus`; the server supplies `makeTransactionDriver(database)` (`platform/database/transaction-driver.ts`, three lines over slonik's depth-aware `withTransaction`) and `CqrsRuntimeModule` builds both once. A command handler declares the transaction once: `return this.unitOfWork.run<XResult>(async () => { … })`. **An `Err` returned from the block rolls the transaction back** and discards deferred events; a thrown error does the same and propagates as a defect. `TransactionFailed` (a constraint escaping to the boundary) is a defect; a driver outage surfaces as `Err(PersistenceUnavailable)`. `dispatch` hands events to the ambient `DeferralSink` **before** any immediate handler runs, and dies with `EventDispatchedOutsideUnitOfWork` when no scope is open — a forgotten `run` fails fast. Nested `run` opens a **savepoint**: a caught nested `Err` rolls back only the savepoint while the outer commits (auth's sign-in around the user module's create). The **subscription** picks the consistency model, never the publisher: `subscribe` (immediate; runs in the publisher's async context and transaction, a throw rolls the publisher back — wallet-on-organization-created), `subscribeAfterCommit` (eventual; the outermost `run` drains after commit, each handler in its own transaction, failures logged to `UnhandledFailures`), `stream` (post-commit, never awaited — the saga substrate). Default new cross-aggregate reactions to `subscribeAfterCommit`. An event adapter is an `@Injectable()` implementing `OnModuleInit` that subscribes in `onModuleInit`. In-memory drain for now (lossy on commit-then-crash); the transactional outbox is the deferred follow-up.
- **`@nestjs/cqrs`'s `EventBus`, `@EventsHandler`, `@Saga`, `ofType`, `IEvent`, `IEventHandler` are forbidden** (`no-nest-event-bus`, and `no-whole-nest-cqrs-imports` refuses `import * as`). `publish` is fire-and-forget over RxJS: a handler runs on a later tick outside the publisher's `AsyncLocalStorage` scope, so it neither joins the transaction nor waits for the commit. Reach the `DomainEventBus` token instead.
- **Ports vs Lives; the domain never names a library.** `domain/` reaches the event vocabulary through `platform/ddd/contracts/domain-event.ts` (`Event.make`, `DomainEvent`) and `PersistenceUnavailable` through `platform/ddd/contracts/persistence-unavailable.ts`; `domain-isolation` allowlists that folder, not package paths. The bus token is `platform/ddd/event-bus.ts` (`DomainEventBus`), one level outside `contracts/`, which keeps a bus out of a domain port's reach; the unit-of-work token is `platform/ddd/unit-of-work.ts`. `makeEventBus`, `makeUnitOfWork` and `makeUnhandledFailures` are fenced to `platform/cqrs/` and `test-utils/` (`bus-factories-at-composition-roots`); `makePolicyRegistry`, `makeResourceResolverRegistry`, `makeHasPermissions` to `platform/auth/` and `platform/modules/`.
- **Composition roots.** `main.ts` (`NestFactory.create(AppModule)`) and `test-utils/test-server.ts` (`Test.createTestingModule({ imports: [AppModule] })` with overrides) share `platform/modules/application-modules.ts` verbatim. `CqrsRuntimeModule`, `AuthzModule`, `BillingGatewayModule` and `DatabaseModule` are `@Global()` because a root-module provider is **not** visible to a feature module — Nest resolves only through explicit `imports`. Everything a module needs from a peer, it imports in its own `<feature>.module.ts` (ADR-0032).
- **DI tokens are abstract classes; every injection names its token.** There is no `emitDecoratorMetadata`, so `constructor(private readonly x: X)` alone injects nothing — write `@Inject(X) private readonly x: X` everywhere. A port is `abstract class XRepository { abstract findOne(…) }`. A library type that must double as a token is a declaration merge: `export interface Database extends DatabaseClient {}` + `export abstract class Database {}` (`platform/database/database.ts`; likewise `DomainEventBus`, `UnitOfWork`, `EnvVars`, `CommandSpanAttributes`). Those files are exempt from `consistent-type-definitions` / `no-empty-interface` in `.oxlintrc.json` because `oxlint --fix` would rewrite the interface into a type alias and break the merge (ADR-0025) — extend the override when you add one.
- **Spans: boundary + use-case** (ADR-0012). The buses open `command.*` / `query.*`, the event bus `event.<Tag>` / `event.afterCommit.<Tag>`, the authorizer `authz.hasPermissions.<resource>.<action>`, and `@opentelemetry/auto-instrumentations-node` (loaded via `tsx --import ./src/instrumentation.ts`) covers HTTP and pg. A handler adds attributes with `trace.getActiveSpan()?.setAttribute(…)`; it does not open its own span. Extractors are the `xCommandSpanAttributes` / `xEventSpanAttributes` maps folded in `CqrsRuntimeModule` (`mergeUnique` throws on a duplicate key across modules).
- **HTTP kernel** (`platform/http/`). `@Endpoint(route)` reads method, path and success status from the contract's `RouteDefinition` (`toExpressPath` turns `{orgId}` into `:orgId`); `zodPipe(schema)` validates params/query/body and raises a 400 `BadRequest` with the zod issues; `HttpProblem extends HttpException` carries the definition and body; `ProblemFilter` (`APP_FILTER`) serialises. `unwrapOrThrow` re-translates only a raised `NotFound` (a resource resolver's miss) through the optional `HttpProblem` entry; every other raised problem — a denial — passes through. `OpenApiController` serves `/openapi.json` from `buildOpenApiDocument`.
- **Authentication via self-hosted Zitadel as a server-side BFF** (ADR-0016, ADR-0017). The SPA never holds tokens; the server runs the OIDC dance and issues an `HttpOnly` cookie sealed by `CookieCodec` (HMAC). `UserAuthGuard` (`@UseGuards`) reads a bearer or the cookie through the **`Authenticator` port** and sets `request.currentUser`; `@Caller()` reads it. The guard must not import the auth module: a guard named in `@UseGuards()` is evaluated when the controller class is decorated, and the auth module's endpoints name the guard, so the cycle leaves it `undefined` (`Invalid guard passed to @UseGuards()`). `AuthenticatorLive` (`platform/middlewares/`) is the only file that names `auth.platform.ts`. Application code consumes `CurrentUser` (`@org/contracts/Policy`); only `modules/auth/` and `platform/auth/` know about Zitadel.
- **Writing SQL.** Inject `Database` (`@Inject(Database)`); statements are `sql.type(RowSchemas.TodoRow)\`SELECT …\``read with`db.any`/`db.maybeOne`/`db.one`(rows parsed through the zod row schema by slonik's interceptor — a row that does not match is a thrown`DatabaseError`, a defect) and `sql.unsafe\`INSERT …\``run with`db.exec`(returns the row count). Wrap every statement in`translateDatabaseErrors(() => …, onConstraint?)`so an outage is`Err(PersistenceUnavailable)` and a constraint you expect (`unique_violation`on an email) is a domain`Err`; anything else rethrows. Interpolated values are parameters (`$slonik_N`placeholders in logs);`sql.timestamp(date)`for dates; a table name is written literally with its schema, never interpolated. Two statements inside a unit of work run **sequentially** on the one transaction connection — no`Promise.all`. `slonik`is importable only from`packages/database/src/`(root`deny`).
- **Per-module DB schemas** (ADR-0020). Each module owns a Postgres schema named after its folder — `user`, `organization`, `todos`, `wallet`, `auth`, `billing` — plus `platform` for cross-cutting tables (`role`'s data lives in `platform.roles`). Application SQL addresses tables by schema — `"user".users` (quotes required: reserved word), `todos.todos`, `platform.roles` — and never JOINs or writes across schemas; cross-schema FKs exist at DDL only. Enforced by `local/no-cross-schema-sql-access` (`scripts/lint-rules/`, which recognises `sql`, `sql.type(...)`, `sql.fragment` and `sql.unsafe` tags; `SCHEMA_BY_MODULE` maps `role → platform`; an `infrastructure/acl/*.acl-live.ts` may read `public`, the legacy API's schema, while the context it fronts is still hapi's — ADR-0034). Adding a module: write `packages/database/src/migrations/<nnnn>_create_schema_<name>.ts` (`export const up = async (knex) => knex.raw(…)`), register it in the folder's `index.ts` (the static `MigrationSource`), and add `<name>` to `MODULE_SCHEMAS` in `packages/database/src/migrator.ts` — one place, shared by every harness and by `resetAndMigrate`.
- **Migrations** (ADR-0011) run through knex's programmatic migrator, tracked in `knex_migrations`: `pnpm -F @org/database db:migrate`, `db:migrate:test`, `db:reset`. The integration global-setup migrates the test database itself.
