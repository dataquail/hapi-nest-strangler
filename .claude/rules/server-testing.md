# Rule: server test seams

**Scope:** `packages/server/` — read before writing or running tests. The legacy API has its own test seams; see `.claude/rules/legacy-api.md`.
**Backing ADR:** 0009 (testing pyramid).

- **Use-case unit tests** (`commands/`, `event-handlers/`, `interface/events/`) construct the handler class directly — `new CreateTodoHandler(todosFake, PassThroughUnitOfWork)` — over three test-only pieces: the module's `*.repository-fake.ts`, `makeRecordingEventBus()` from **`@org/event-bus/testing`**, and `PassThroughUnitOfWork` (or `makePassThroughUnitOfWork({ eventBus })`) from **`@org/unit-of-work/testing`** — the real boundary over an in-memory driver, so a subject that dispatches an event gets production's delivery and discard-on-`Err`. No Nest testing module, no DB, no docker. Assert on the returned `Result` (`result.isErr()`, `result.unwrapErr()._tag`); compare a `TaggedError` instance to a plain object with `{ ...error }`.
- **Four test kinds, told apart by filename stem, each with its own allowlist** (the `server-*-test-file` fragments in `packages/server/architecture.yaml`). A _unit_ test names its subject, the server, `vitest`, `oxide.ts` and node. A _use-case_ test adds `@org/event-bus` and `@org/unit-of-work`. An _integration_ test (`*.repository-live.integration.test.ts`, `queries/*.handler.integration.test.ts`) adds `@org/database`. A _unit-of-work_ integration test builds its own unit of work over the test database. Endpoint tests reach `@org/contracts` and the buses they seed through. A test that needs more than its kind grants is a test of the next kind — rename it, don't widen the fragment.
- **Two disjoint suites, selected by file suffix + the `TEST_INTEGRATION` env toggle** (in `vitest.shared.ts`). `pnpm test` runs the **unit** suite — every `*.test.ts` _except_ `*.integration.test.ts`. `pnpm test:integration` (sets `TEST_INTEGRATION=true`, scoped to `@org/server`, `@org/legacy-api` and `@org/database`) runs **only** `*.integration.test.ts`.
- **Integration tests hit a real DB and are dumb** — they do not self-skip. The integration global-setup hard-fails (asserts `DATABASE_URL_TEST` is set — the name must contain `test` — then connects and runs the knex migrations) so a missing DB aborts the run rather than silently skipping.
- **HTTP integration tests** use `useServerTestRuntime(["schema.table", …], { caller })` from `test-utils/server-test-runtime.ts`, which wires `startTestServer` + `beforeAll`/`afterAll` + per-test `truncate`. `startTestServer` builds `Test.createTestingModule({ imports: [AppModule] })` and **overrides** `EnvVars`, `Database`, `Mailer` (→ `MailerFake`), `BillingGateway` (→ `BillingGatewayFake`) and `UserAuthGuard` (→ `UserAuthGuardFake`, which sets `request.currentUser` to the caller you passed — `SUPER_ADMIN_CALLER` / `MEMBER_CALLER` from `fake-auth-guard.ts`), then listens on port 0. Tests exercise the contract via the returned `openapi-fetch` client (`server().client.POST("/orgs/{orgId}/todos", …)`) and seed prior state by calling _other endpoints_ or dispatching through `server().commandBus`, not by reaching into module internals. `server().mailer.sent` and `server().billingGateway` are the observable fakes.
- **Query/repository integration tests** seed via the live repository (or other production-path code), not via raw SQL; `createTestDatabase` / `truncate(db, "todos.todos")` from `test-utils/test-database.ts`.
- **Handler coverage is a unit test.** `<feature>.handlers.test.ts` calls `assertHandlersCover("command", xCommands, xCommandHandlers)` (and the query pair) from `platform/cqrs/messages.ts`, which reads the `__commandHandler__` / `__queryHandler__` metadata `@nestjs/cqrs` stamps and fails on an unrouted message, a duplicate, or a handler for a message the module does not declare.
- **Coverage is one merged number, and it gates CI.** `pnpm test:coverage:unit` and `pnpm test:coverage:integration` write Vitest **blob** reports into `.vitest-reports/`, and `pnpm coverage:merge` folds them and checks the thresholds in the root `vitest.config.ts` (root-only — a project config's `test.coverage` is ignored in workspace mode). They are a **ratchet**: raise a floor when coverage rises, never lower one to make a red build green. Process entrypoints (`main.ts`, `instrumentation.ts`, `import "server-only"` modules) are excluded rather than discounted.
- **Endpoint test naming.** `*.endpoint.integration.test.ts` exercises the real HTTP layer against a live database via `useServerTestRuntime`. `*.endpoint.test.ts` is a true unit test — a parity token for endpoints whose meaningful coverage lives elsewhere (the OIDC `login` / `logout` flows, covered by Playwright and the `SessionRepositoryLive` integration test). The `login`/`logout` endpoints are the two `requiresNot` exemptions on the endpoint parity rule; every other endpoint must have `*.endpoint.integration.test.ts`. Any `.endpoint.test.ts` must carry a header comment naming where the meaningful coverage lives.
- **Under full-suite load** an endpoint test can exceed its timeout while it passes alone; rerun before treating it as a failure, and prefer seeding through the bus over a chain of HTTP calls when a test is slow by construction.
